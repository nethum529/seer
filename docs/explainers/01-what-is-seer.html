Explainer 01

What is Seer?

Seer is a terminal multiplexer for people who run coding agents and shells on one Linux machine. A friend can join from Linux or macOS with one paste.

Who it is for

Seer starts with two simple roles. The owner supplies the Linux machine. A friend brings only a terminal.

1

The owner

You run coding agents and normal commands in terminal panes on your Linux machine. You start one Seer server and send an invitation.

2

The friend

Your friend uses Linux or macOS. They paste one install and join line. They do not need Rust, Git, a GitHub account, a VPN, or a port-forward rule.

Why Seer exists

SSH and tmux are useful tools. Their normal setup does not give this complete friend flow. Seer makes the narrow sharing job one product feature.

Tool Friend entry Shared work model
Plain SSH Needs a reachable SSH service and user authentication. Gives a remote shell. It does not supply a Seer workspace tree or read-only peek.
tmux Has no single share command. Cross-user access needs local access rules, file permissions, and a socket selector. Clients attach to a shared tmux server and session.
Seer Uses one pasted line with a single-use invitation. Each person gets a private tree. A person can view another tree with read-only peek.

The important difference

A friend does not enter the owner's terminal view. Seer gives that friend a separate runtime. A runtime is the server process that owns one person's terminal work. It keeps that person's workspace, tabs, panes, shells, and terminal state apart from other people.

Seer is service-only. The remote connection reaches the Seer protocol. It does not create a VPN route, file transfer service, or port-forward service. A writable Seer pane still gives a shell on the host by design.

Built now

The multiplayer path works

The repository has the Linux server, Linux and macOS clients, single-use invitations, a private runtime for each person, terminal cell rendering, and read-only cross-user peek. Durable restore after a runtime or host restart is planned work. Detach only closes a client connection, so running panes stay on the live server.
