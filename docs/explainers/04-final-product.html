Final product vision

A shared server with a private place for each person.

Seer grows from a working terminal multiplexer into a durable home for coding agents. The terminal UI comes first. A desktop app comes much later.

The product model

The server owns the work. Each client is a view and control surface.

In progressBrokerThe one entry process. It checks identity and routes clients. Wave 2 adds full runtime supervision.
BuiltRuntimeOne server process for one person. It owns that person's workspaces and PTYs.
In progressOS identityThe Linux account, home, shell, groups, files, and process rights for one person.
In progressCold restoreA restart rebuilds saved structure and starts replacement shells. It does not recover old process memory.

Seven commands stay simple

This is the complete common command surface from the command UX research.

CommandStatusOne job
seer startBuiltStart the one Linux server.
seer inviteBuiltMake one unused seat.
seer joinBuiltClaim a seat, pick a name, and attach.
seer listBuiltShow saved servers and people.
seer attachBuiltConnect to your own tree.
seer detachBuiltRemove one client. Keep panes alive.
seer peek <person>BuiltView another tree. Never send input.

Boundaries that do not move

These are settled project decisions.

BuiltServer work stays on the server.PTYs, shells, and coding agents never run on the client. The broker never owns those child processes.
BuiltPlatform scope stays small.The server is Linux. Clients are Linux and macOS. Windows is not supported.
