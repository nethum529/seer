Working MVP

One line. One name. One shell.

The owner runs Seer on Linux. A friend on Linux or macOS pastes one line. Seer gives each person a private terminal workspace on the owner's server.

The shell runs on the Linux server. The friend uses a local terminal only. The server owns the shell process and the pseudo-terminal, or PTY.

Four small words to know

These words describe where the state lives.

BrokerThe one server process that checks identity and routes connections.
RuntimeThe process that owns one person's terminal state.
TreeA person's workspaces, tabs, and panes. A pane holds one terminal.
AttachConnect a client to its own live tree. Detach removes only that client.

Leave, look, and return

Peek means a read-only view of another person's tree.

bob@mac:~$ seer list
SERVER    YOU  STATE     PEOPLE
01234567  bob  detached  alice, bob

bob@mac:~$ seer peek alice
PEEK: alice - READ ONLY
Workspace: alice/current
bob@mac:~$ seer detach
Detached from 01234567. Your panes are still running.

bob@mac:~$ seer
Attached to 01234567 as bob.

The MVP contract

These nine user-facing checks define a working multiplayer MVP.

T1 BUILTBroker listens

One broker accepts Seer connections.

T2 BUILTValid login works

A saved identity gets its own tree.

T3 BUILTTab and shell open

An empty tree gets one tab and one shell pane.

T4 BUILTShell round trip works

Input reaches the shell. Output returns.

T5 BUILTDetach keeps work alive

The client leaves. Its live panes continue.

T6 BUILTUser trees stay separate

Each person has a separate runtime and tree.

T7 BUILTPeek is read-only

A viewer cannot send terminal input.

T8 BUILTBad token is refused

An invalid login does not enter.

T9 BUILTStop peek returns home

The client receives its own tree again.
