Explainer 02

How Seer works

The Linux server does the terminal work. A client on Linux or macOS sends input and draws the terminal cells that the server sends back.

Three parts, three jobs

1

Broker

The broker is the front door. It owns identity, single-use seats, routing, runtime supervision, and metadata. It never owns a PTY, shell, or coding agent process.

2

Runtime

Each person gets one runtime process. It owns that person's workspace tree, PTYs, shells, and terminal cell grids. Work from two people stays in two runtimes.

3

Client

The client is the local Seer view. It draws cells and sends keys or layout commands. The client does not run the server shell or own its PTY.

How a friend joins

A capsule is the paste-safe invitation. It contains the server public key and one seat token. A seat is permission for one new person to join.

  1. Make a seatThe owner runs seer invite. The seat expires and works once.
  2. Send one lineThe owner sends the printed install and join line. The capsule contains no person name.
  3. Name the personThe friend pastes the line. Seer asks for a name on this first join.
  4. AttachThe broker marks the seat used, records the person, starts that person's runtime, and opens the first shell.

The seat token is only for first join. Seer saves a separate person credential for later attach. A used or expired seat cannot add another person.

The workspace tree

Tree means the ordered structure of workspaces, tabs, and panes. Each runtime owns one tree.

Workspace

The top group for one area of terminal work. A workspace contains tabs.

Tab

One view inside a workspace. A new tab starts with one pane and one shell.

Pane

A terminal rectangle inside a tab. Each pane has a server-side PTY, shell, size, and cell grid.

Built now

Peek shows work without control

seer peek <name> asks the broker for another person's workspace. The broker routes the connection to that person's runtime in read-only mode. The broker and runtime drop terminal input and layout changes. The client keeps a read-only banner visible. Stop peek returns the client to its own runtime.

The remote path is encrypted

The capsule gives the client the broker's iroh public key. Iroh authenticates that key inside an encrypted QUIC connection. It tries a direct path through home network address translation. If that path fails, it uses a relay. The relay carries encrypted bytes and cannot read terminal data. The connection accepts the Seer protocol only. It does not create a network interface, route, or DNS change.

Server boundary: PTYs, shells, and coding agent child processes always stay on the Linux server. They never move to the client.

Source basis: ADR 0002, session lifecycle research, and the crate sources.
